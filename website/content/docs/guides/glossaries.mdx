---
title: Glossaries
description: Learn reusable ASR corrections and terminology without turning one-off edits into global rules.
---

A glossary stores canonical source terms, known ASR aliases, translation
targets or keep rules, notes, and domain context under
`$OPENBBQ_HOME/glossaries/`.

## Automatic scope for one-prompt tasks

An explicit `--glossary NAME` always wins:

```bash
openbbq --json agent init '<source>' --workspace workspaces/demo --to zh --glossary project-name
```

Without one, a URL task waits until fetch discovers the author and derives a
stable author-and-target glossary name. Later videos from the same author and
target language reuse that glossary. A local file without an explicit glossary
keeps its learning in the task only because author scope is unknown.

The Agent does not choose among global glossaries by semantic guesswork.

## Task-local overlay

During the task, new learning is written to
`.openbbq/glossary-overlay.json`. Base glossary plus overlay are immediately
visible to segmentation and later translation batches, but the global library
is not modified mid-run.

When translation corrects an obvious ASR occurrence, OpenBBQ records a glossary
candidate containing:

- canonical corrected source text;
- the observed ASR alias;
- evidence and origin;
- whether the Agent marked it reusable.

A reusable correction is promoted into the overlay automatically. The Agent
must not duplicate the same correction as a manual glossary update.

## Safe publication

After successful delivery, OpenBBQ publishes reusable non-conflicting overlay
entries to the bound global glossary. Publication is idempotent and never
overwrites an incompatible existing term. A conflict or permission failure does
not block the subtitle video; the overlay remains in the workspace and `done`
returns a structured retry warning.

Failed or unfinished tasks do not publish their overlay.

## Glossary fields

| Field | Meaning |
| --- | --- |
| `source` | Canonical source spelling and ASR bias term. |
| `target` | Required canonical translation when present. |
| `aliases` | Confirmed alternate or ASR forms corrected to `source`. |
| `note` | Context supplied to translation batches. |
| `keep` | Preserve source spelling in target text. |

Terms with only a note and no target are still included when relevant, so the
Agent can use their context without inventing a fixed translation.

## Expert library commands

Create, inspect, and explicitly bind a glossary:

```bash
openbbq glossary new project-name --context "Technical interviews about developer tools"
openbbq glossary list
openbbq glossary show project-name
openbbq glossary use project-name --workspace workspaces/demo
```

The compatibility interface also exposes deterministic suggestions, full
transcript audit batches, and atomic curated updates:

```bash
openbbq glossary suggest --workspace workspaces/demo
openbbq glossary audit --workspace workspaces/demo --offset 0 --limit 20
openbbq glossary apply --workspace workspaces/demo glossary-terms.json
```

These are expert tools, not required steps in the normal one-prompt flow.
